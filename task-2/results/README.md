## Итоговое решение

Основываясь на текущем состоянии системы, у компании уже существует k8s кластер. И оптимальным решением будет внедрить k8s cronjobs.
Оно легко интегрируется с текущей инфраструктурой практически без дополнительных накладных расходов и отлично подходит для подобных несложных задач.

Весь мониторинг может происходить через уже встроенные в кластер инструменты.

Чтобы хранить данные можно использовать s3 хранилище, либо прибегнуть к комбинации filesystem + postgres (создается доп таблица со ссылками на файлы).
Последний вариант будет выгоднее, если csv файлы – единственные файлы в системе, чтобы не разворачивать s3 только ради одной cron job.

## Имплементация

Итоговым решением будет простой скрипт, например на python.

0) Подготавливаем скрипт, который будет подтягивать и агрегировать данные по sql, затем складывать в хранилище.
1) Настраиваем k8s, создаем спецификацию cronjob, secrets, configmap.
2) Используем уже имеющиеся инструменты для мониторинга работы.

# Сравнение решений для пакетной выгрузки данных

| Критерий                 | Spring Batch | Apache Airflow | Kubernetes Job | Apache Spark |
|--------------------------|--------------|----------------|----------------|--------------|
| CRON-расписание          | Да           | Да             | Да             | Нет          |
| Сложность реализации     | Средняя      | Средняя        | Низкая         | Высокая      |
| Ресурсоёмкость           | Средняя      | Средняя        | Низкая         | Высокая      |
| Масштабируемость         | Хорошая      | Хорошая        | Хорошая        | Отличная     |
| Интеграция с облаком     | Хорошая      | Хорошая        | Отличная       | Хорошая      |
| Логирование и мониторинг | Хорошая      | Отличная       | Хорошая        | Хорошая      |

## Вывод

Для задачи ежедневной выгрузки оптимальным решением является Kubernetes Job,
ввиду низкой сложности реализации, минимальных требований к ресурсам
и легкой интеграции с микросервисной архитектурой.

# План внедрения модуля выгрузки данных

## Этапы реализации

1. Разработка Python-сервиса для экспорта данных
2. Реализация SQL-запросов с JOIN таблиц
3. Контейнеризация с помощью Docker
4. Создание Kubernetes CronJob
5. Настройка мониторинга
6. Настройка алертинга
7. Тестирование решения
8. Развёртывание в production

## Конфигурация

- PostgreSQL credentials через Secrets
- CRON: 0 6 * * *
- Логи отправляются в ELK
- Метрики в Prometheus

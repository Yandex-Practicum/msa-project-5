## Сравнительный анализ технологий
| Технология | Плюсы | Минусы | Вердикт |
| --- | --- | --- | --- |
| Spring Batch | 1. Мощный фреймворк для пакетной обработки. <br>2. Транзакционность <br>3. Автоматический перезапуск | 1. Тяжеловесность для простой выгрузки (нужен отдельный микросервис).<br>2. Требует написания кода и сборки.<br>3. Долгий запуск JVM. | Избыточно |
| Apache Airflow | 1. Отличные возможности оркестрации, дашборды.<br>2. Управление зависимостями DAG.<br>3. Логирование. | 1. Нужно разворачивать отдельный кластер <br>2. Слишком сложен для одного триггера по времени.| Избыточно |
| Apache Spark | 1. Быстрая обработка больших данных (in-memory).<br>2. Параллелизм. | 1. Избыточно. 10 тыс. строк обработаются быстрее, чем поднимется драйвер Spark.<br>2. Огромное потребление ресурсов. | Избыточно |
| K8s CronJob | 1. Нативное решение для существующей инфраструктуры (K8s).<br>2. Изоляция задач (Pod создается и умирает).<br>3. Нет расходов на простаивающие сервисы. | 1. Нужно создать образ контейнера.<br>2. Нужно где-то хранить CSV (Volume/Облачное хранилище). | Оптимально |

## Решение
Итоговый выбор: Kubernetes CronJob

- Соответствие инфраструктуре: микросервисы в облаке и Kubernetes, планировщик уже есть в кластере
- Цена: CronJob запускает под на 1-2 минуты и завершает его. Оплата только за фактическое время выполнения (в отличие от постоянно висящего микросервиса на Spring Boot).
- Простота: нет сложной логики обработки (нужен только SQL JOIN), код будет простым скриптом.

## Верхнеуровневый план имплементации
Предлагается сделать Python-скрипт (из-за простоты работы с CSV и БД), обернуть его в Docker-образ и запускать через CronJob.
- Ежедневно в 6:00 по Московскому времени:
  - Kubernetes автоматически создаёт Job из спецификации CronJob
  - Запускается контейнер с легковесным скриптом (Python/Go)
- Скрипт выполняет sql запрос:
```sql
SELECT 
  c.client_name,
  p.product_name,
  cat.category_name,
  cp.price
FROM client_prices cp
JOIN clients c ON cp.client_id = c.id
JOIN products p ON cp.product_id = p.id
JOIN categories cat ON p.category_id = cat.id
WHERE cp.active = true
```
  - Формирует отдельный CSV-файл для каждого клиента
  - Сохраняет файлы в примонтированный том (S3/NFS)
- После завершения:
  - Логи автоматически отправляются в Loki
  - Метрики (время выполнения, количество строк) доступны в Prometheus
  - При ошибке — алерт в мониторинг, автоматический ретрай

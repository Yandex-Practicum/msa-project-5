# Сравнение технологических решений для пакетной обработки данных

| Критерий | Spring Batch | Apache Airflow | K8s CronJob | Spark |
|----------|--------------|----------------|-------------|-------|
| **Наличие конфигурации CRON-расписания** | ✅ Через @Scheduled или Quartz | ✅ Нативная поддержка CRON | ✅ Нативная поддержка CRON | ⚠️ Требуется внешняя оркестрация (Airflow/Oozie) |
| **Сложность реализации логики по обработке данных** | ⚠️ Средняя (требует изучения фреймворка) | ✅ Низкая (Python-скрипты) | ✅ Низкая (любой язык) | ❌ Высокая (требует экспертизы) |
| **Ресурсоёмкость решения** | ✅ Низкая (легковесный) | ❌ Высокая (тяжелый оркестратор) | ✅ Минимальная (запускается по расписанию) | ❌ Очень высокая (требует кластер) |
| **Масштабируемость** | ⚠️ Средняя (вертикальная) | ✅ Высокая | ✅ Высокая (горизонтальная) | ✅ Очень высокая |
| **Сложность развёртывания в облаке** | ✅ Низкая (Jar-файл в K8s) | ❌ Высокая (требует отдельный кластер) | ✅ Минимальная (нативный K8s ресурс) | ❌ Очень высокая (Spark on K8s) |
| **Интеграция с микросервисами** | ✅ Отличная (Spring ecosystem) | ⚠️ Средняя (внешний сервис) | ✅ Отличная (Sidecar/отдельный pod) | ❌ Сложная |
| **Интеграция с логированием и мониторингом** | ✅ Отличная (Prometheus/Grafana) | ✅ Отличная (встроенный UI) | ⚠️ Средняя (через K8s tools) | ✅ Хорошая |

---

## Итоговый выбор: **Kubernetes CronJob**

### Обоснование:

| Фактор | Оценка |
|--------|--------|
| **Соответствие задаче** | Простая выгрузка данных без сложной логики |
| **Инфраструктура** | Уже используется Kubernetes в компании |
| **Стоимость** | Минимальная (нет дополнительных сервисов) |
| **Время реализации** | 2-4 недели до production |
| **Поддержка** | Стандартный K8s ресурс, не требует отдельной команды |

### Ключевые преимущества:

1. **Экономия ресурсов** — запускается только в 6:00, не потребляет ресурсы круглосуточно
2. **Нативная интеграция** — работает в существующем K8s-кластере без дополнительных компонентов
3. **Простота мониторинга** — стандартные K8s-метрики + Prometheus/Grafana
4. **Надёжность** — встроенные механизмы retry, alerting и история запусков
5. **Безопасность** — использование K8s Secrets и RBAC для доступа к БД и хранилищу


### Почему не другие решения:
**Spring Batch:** Избыточен для простой выгрузки, требует изучения фреймворка
**Apache Airflow:** Overkill для одной задачи, требует отдельного кластера и поддержки
**Spark:** Полностью избыточен для 10K строк, высокая стоимость инфраструктуры

# Как работает решение to be

1. Каждый день в 6 утра k8s cronjob запускает docker container со скриптом.
2. В контейнере python скрипт подключается к postgres, получает необхожимые данные, собирает join в pandas, формирует csv
3. Скрипт сохраняет файлы в s3/gcs с уникальным таймстампом
4. По завершении отправляется уведомление по email (при ошибке - уведомление об ошибке)

# Верхнеуровневый план конфигурации и имплементации

1. Реализовать python скрипт. Он будет читать из Postgres, собирать dataframes и выгружать в csv, заливать в object storage, отправлять уведомление. Собрать docker образ
2. Настройка kubernetes. Создать secrets для хранения секретов, configmap с параметрами (bucket name, export path)
3. Создание k8s cronjob. Прописать cronjob с расписанием "0 6 * * *". В spec.template запустить docker контейнер со скриптом
4. Мониторинг/алерты. Логи контейнеров собираются через fluentd в ElasticSearch. Метрики cronjob отображаются в prometheus + grafana. Обработка ошибок в python, уведомления по email.
5. Тестирование. Прогнать cronjob вручную + проверить корректность csv в s3
6. Выход в прод. Применить cronjob манифест в namespace prod

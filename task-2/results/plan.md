# Верхнеуровневый план конфигурации и имплементации модуля пакетной генерации прайс-листов

## Обзор решения

**Технологический стек:**
- Python 3.12: psycopg (курсорное чтение), csv / openpyxl (XLS), boto3 (S3)
- Kubernetes CronJob (запуск по расписанию `0 6 * * *`)
- PostgreSQL (источник данных)
- S3-совместимое объектное хранилище для готовых прайс-листов
- Prometheus + Grafana + kube-state-metrics (метрики и алерты), общий стек логирования кластера

## Этап 1: Подготовка инфраструктуры

### 1.1 База данных магазина
- Проверить наличие индексов на внешних ключах `client_prices(product_id, client_id)`, `products(category_id)`
- Создать read-only пользователя `price_export_ro` с правом SELECT на products, categories, clients, client_prices
- Сохранить креды в Kubernetes Secret

### 1.2 Хранилище прайс-листов
- Создать бакет `price-lists` в объектном хранилище, структура путей `/price-lists/{client_id}/{yyyy-MM-dd}.csv`
- Настроить lifecycle-политику (хранение выгрузок, например, 90 дней)
- Выдать сервисный ключ с правом PUT/GET, настроить HTTPS-доступ клиентов к своим каталогам

### 1.3 Namespace и секреты Kubernetes
- Создать namespace `batch`
- Создать Secrets: подключение к БД магазина, ключи S3, параметры Notification Service

## Этап 2: Разработка скрипта-экспортера

### 2.1 Скрипт `generate_pricelists.py`
- Подключение к PostgreSQL, один SELECT с JOIN четырёх таблиц, курсорное чтение чанками по ~1 000 строк
- Группировка строк по клиенту, формирование персонального CSV (опционально XLS) на каждого B2B-клиента
- Загрузка файлов в S3 по путям `/price-lists/{client_id}/{date}.csv` (идемпотентно: файл за дату перезаписывается целиком)
- Структурированные JSON-логи (число обработанных строк и сформированных файлов), уведомление об успехе/сбое
- Корректные exit codes: 0 — успех, 1 — ошибка (для ретраев Kubernetes)

### 2.2 Тесты
- Unit-тесты скрипта; проверка идемпотентности повторного запуска за ту же дату

## Этап 3: Контейнеризация и манифесты Kubernetes

### 3.1 Docker-образ
- Минимальный Dockerfile на базе `python:3.12-slim`, установка зависимостей, `CMD ["python", "generate_pricelists.py"]`
- Сборка и публикация образа в Container Registry через CI

### 3.2 CronJob-манифест
- `schedule: "0 6 * * *"`, `startingDeadlineSeconds` (гарантия старта), `concurrencyPolicy: Forbid`
- `backoffLimit: 2` (повторные попытки при падении пода), `activeDeadlineSeconds` (защита от зависания)
- `successfulJobsHistoryLimit` / `failedJobsHistoryLimit` (история запусков)
- Resources: requests/limits ~128–256 МБ RAM
- Подключение Secrets через `envFrom`, ServiceAccount с минимальными правами

## Этап 4: Наблюдаемость

### 4.1 Метрики
- kube-state-metrics → Prometheus: `kube_job_status_succeeded`, `kube_job_status_failed`, `kube_job_duration_seconds`
- Дашборд Grafana: статус последнего запуска, длительность (тренд), failure rate

### 4.2 Алерты
- Нет успешного запуска к 06:30
- Job завершился с ошибкой после исчерпания retries (`kube_job_status_failed > 0`)
- Длительность запуска выше порога (например, 30 минут)
- Подозрительно малая выгрузка: число строк или файлов в логах резко ниже обычного — возможна проблема с исходными данными (Job при этом завершится «успешно»)

### 4.3 Логирование
- JSON-логи скрипта в stdout пода → сбор в общий стек логирования кластера; история Job-ов — через `kubectl get jobs`

## Этап 5: Тестирование

### 5.1 Проверка на staging
- Прогон Job-а на staging-БД с тестовым набором данных, проверка содержимого CSV и идемпотентности

### 5.2 Нагрузочная проверка
- Прогон на объёмах 10 000 / 20 000 строк `client_prices`: замер длительности и памяти пода, калибровка resources

## Этап 6: Вывод в эксплуатацию

- Применение манифестов в production, пробный ручной запуск (`kubectl create job --from=cronjob/price-list-export test-run`) с проверкой файлов в S3
- Проверка алертов: имитация сбоя (недоступность S3), контроль ретраев и уведомления
- Передача дата-инженеру инструкции: ручной перезапуск за дату, чтение логов и истории Job-ов

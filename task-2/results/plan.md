# Верхнеуровневый пошаговый план конфигурации и имплементации системы генерации прайс-листов

## Этап 1: Подготовка инфраструктуры

1. **Проверка готовности Kubernetes-кластера**
   - Убедиться, что кластер работает и доступен
   - Проверить наличие прав на создание CronJob, ConfigMap, Secret
   - Убедиться в доступности хранилища контейнеров (registry)

2. **Создание изолированного пространства**
   - Создать отдельный namespace для системы генерации прайс-листов
   - Настроить сетевые политики при необходимости

3. **Подготовка доступа к внешним ресурсам**
   - Настроить доступ к PostgreSQL из pod'ов CronJob
   - Настроить доступ к S3-compatible хранилищу
   - Создать service account с минимально необходимыми правами

---

## Этап 2: Настройка базы данных

4. **Создание пользователя для выгрузки данных**
   - Создать отдельного пользователя БД с правами только на чтение
   - Предоставить доступ к необходимым таблицам: products, categories, clients, client_prices

5. **Оптимизация запросов**
   - Создать материализованное представление или VIEW для объединения данных из всех таблиц
   - Протестировать производительность запроса на полном объёме данных
   - При необходимости добавить индексы для ускорения выборки

6. **Документирование схемы данных**
   - Зафиксировать структуру выходных данных для генерации CSV/XLS
   - Согласовать формат файлов с заказчиком (B2B-клиентами)

---

## Этап 3: Разработка приложения CronJob

7. **Проектирование архитектуры приложения**
   - Определить модули: подключение к БД, генерация файлов, загрузка в хранилище, логирование, метрики
   - Выбрать язык реализации (Python/Go) и библиотеки для работы с PostgreSQL, CSV, S3

8. **Реализация базовой логики**
   - Написать модуль подключения к PostgreSQL и извлечения данных
   - Реализовать генерацию CSV/XLS файлов с группировкой по клиентам
   - Добавить модуль загрузки файлов в S3-хранилище

9. **Добавление наблюдаемости**
   - Интегрировать сбор метрик (Prometheus): время выполнения, количество файлов, статус запуска
   - Настроить структурированное логирование (JSON-формат) для интеграции с ELK/Loki
   - Реализовать обработку ошибок и graceful shutdown

10. **Контейнеризация**
    - Создать Dockerfile с минимальным образом для запуска приложения
    - Настроить health-check endpoint для метрик
    - Протестировать образ локально

---

## Этап 4: Конфигурация Kubernetes

11. **Подготовка конфигурационных артефактов**
    - Создать ConfigMap с параметрами подключения к БД и S3
    - Создать Secret с учётными данными (пароли, ключи доступа)
    - Настроить переменные окружения для гибкой конфигурации

12. **Настройка CronJob**
    - Определить расписание запуска (ежедневно в 6:00)
    - Настроить политику параллельного выполнения (Forbid)
    - Задать лимиты ресурсов (CPU, memory) для pod'а
    - Настроить restartPolicy и историю завершённых задач

13. **Настройка безопасности**
    - Создать ServiceAccount для CronJob
    - Настроить RBAC с минимальными необходимыми правами
    - Ограничить доступ к Secret'ам только для нужных pod'ов

14. **Интеграция с хранилищем**
    - Настроить доступ CronJob к S3/MinIO
    - Определить структуру директорий для сохранения файлов
    - При необходимости настроить lifecycle-политики для старых файлов

---

## Этап 5: Настройка мониторинга и алертинга

15. **Интеграция с Prometheus**
    - Настроить ServiceMonitor для автоматического обнаружения метрик
    - Проверить сбор метрик: длительность выполнения, количество файлов, статус запуска

16. **Создание дашбордов в Grafana**
    - Визуализировать ключевые метрики: время выполнения, успешность запусков, объём обработанных данных
    - Добавить панель с историей запусков и статусами

17. **Настройка алертов**
    - Создать правило для оповещения при неудачном завершении задачи
    - Настроить алерт при превышении допустимого времени выполнения
    - Добавить уведомление при отсутствии новых файлов за 24 часа

18. **Настройка каналов уведомлений**
    - Интегрировать Alertmanager с email/Telegram/Slack для доставки алертов
    - Настроить эскалацию критических инцидентов

---

## Этап 6: Интеграция с внешними системами

19. **Настройка доступа для B2B-клиентов**
    - Организовать механизм скачивания файлов: presigned URL, FTP, API
    - При необходимости реализовать отправку email-уведомлений со ссылками на файлы

20. **Интеграция с системами логирования**
    - Настроить отправку логов в централизованную систему (ELK/Loki)
    - Добавить correlation-id для отслеживания выполнения конкретной задачи

21. **Документирование API и процессов**
    - Описать формат файлов и структуру данных для клиентов
    - Создать runbook для операционной поддержки системы

---

## Этап 7: Тестирование и запуск в production

22. **Локальное и интеграционное тестирование**
    - Протестировать приложение на тестовой БД с репрезентативным объёмом данных
    - Проверить генерацию файлов для разных сценариев (пустые данные, ошибки БД, недоступность S3)

23. **Тестирование в staging-окружении**
    - Развернуть CronJob в staging-namespace
    - Запустить задачу вручную и проверить полный цикл: БД → генерация → S3 → метрики
    - Проверить работу алертов и дашбордов

24. **Нагрузочное тестирование**
    - Оценить время выполнения на полном объёме данных (10K+ строк)
    - Убедиться, что укладываются в отведённое окно выполнения
    - При необходимости оптимизировать запросы или увеличить ресурсы

25. **План развёртывания в production**
    - Подготовить rollback-план на случай неудачного деплоя
    - Согласовать окно запуска с бизнесом
    - Выполнить деплой и запустить первый ручной запуск для валидации

26. **Мониторинг после запуска**
    - Контролировать первые несколько автоматических запусков
    - Собрать обратную связь от B2B-клиентов по качеству и доступности файлов
    - При необходимости скорректировать расписание или формат выгрузки

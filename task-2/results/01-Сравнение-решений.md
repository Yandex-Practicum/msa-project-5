# Задание 2. Сравнение решений для ежедневной выгрузки прайса (06:00)

Контекст: простая связка таблиц PostgreSQL и выгрузка CSV 5–10 тыс. строк; без сложной бизнес-логики (см. текст проектной работы в курсе / файле `Задание.txt` у себя локально).

| Критерий | Spring Batch | Apache Airflow | K8s Job / CronJob | Apache Spark |
|----------|--------------|----------------|-------------------|--------------|
| CRON / расписание | Да (Scheduler, внешний cron, K8s CronJob) | Да (`schedule` в DAG) | Да (CronJob) | Обычно внешний оркестратор (Airflow, cron) |
| Сложность логики обработки | Средняя: Java, шаги Job/Step | Высокая гибкость (Python, ветвления, DAG) | Минимальная: один скрипт/процесс | Высокая для больших данных |
| Ресурсоёмкость | JVM + БД; умеренно | Планировщик + воркеры; выше для маленьких job | Низкая для одного pod | Высокая (кластер) |
| Масштабируемость | Параллельные шаги, partitioning | Масштабирование воркеров | Реплики Job, отдельные очереди | Очень высокая для TB |
| Облако и MSA | Docker/K8s, рядом с Java-сервисами | Cloud Composer, MWAA, свой K8s | Нативно в K8s | Dataproc, EMR, k8s |
| Логи и мониторинг | Логи приложения, Micrometer, ELK | Встроенный UI, интеграции | Логи pod, Prometheus | Spark UI, метрики |

## Вывод

Для **простой ежедневной выгрузки** без тяжёлых трансформаций достаточно **Kubernetes CronJob** + небольшой скрипт или **лёгкий Spring Batch** Job по расписанию. **Spark** избыточен. **Airflow** уместен, если тот же оркестратор уже используется для других пайплайнов (как в задании 1).

**Выбранный вариант для To Be:** **K8s CronJob** + контейнер с экспортом SQL→CSV (минимальная связка с микросервисной инфраструктурой в облаке, предсказуемое расписание). Альтернатива при доминировании Java — один Spring Batch step по cron.

| Критерий | Spring Batch  | Apache Airflow | K8s Job | Spark |
| ---------| ------------- | -------------- | ------- | ----- |
| **Наличие конфигурации CRON-расписания** | Да (Spring Scheduler) | Да (schedule_interval/DAG) | Да (K8s CronJob) | Частично (через Airflow или внешние триггеры) |
| **Сложность реализации логики обработки данных** | Низкая (простые SQL-запросы и маппинг) | Низкая (Python + SQL, операторы работы с БД) | Низкая(скрипт/контейнер)d | Высокая (оверхед для простых SQL выборок) |
| **Ресурсоемкость** | Низкая | Средняя | Низкая | Высокая (JVM, кластеры) |
| **Масштабируемость** | Средняя (можно горизонтально запускать задачи) | Высокая( Executor/Worker) модель | Высокая (параллельные CronJobs) | Очень высокая |
| **Сложность развертывания в облаке / интеграция с микросервисной архитектурой** | Средняя. Требуется JVM, настройка Spring | Средняя. Docker/K8s, Python | Низкая. Контейнер/cronjob | Высокая. требуется Spark cluster |
| **Удобство интеграции с логированием и мониторингом** | Среднее. нужно настроить Spring Actuator, ELK | Высокое. Встроенные логирование, XCom, интеграция с Prometheus/Grafana | Среднее. K8s логи, сторонние системы | Высокое, но сложнее настроить для простого задания |

### Выводы
* Для задачи ежедневной генерации CSV (5-10к строк) оптимально будет использовать K8s Job. Т.к. у нас по тз низкая ресурсоемкость, Airflow будет немного в избытке. А k8s job можно легко развернуть, при необходимости хорошо масштабируется. Но в сравнении с Airflow у него нет встроенного механизма ретраев, фоллбеков.
* Но если позже появятся сложные зависимости между задачами, event-truggers или нужно будет гибко оркестрировать несколькими пайплайнами, то лучше использовать Airflow.

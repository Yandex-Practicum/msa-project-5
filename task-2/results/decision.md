# Обоснование выбора технологического решения

## Сравнительный анализ технологий

| Критерий | Spring Batch | Apache Airflow | K8s Job | Apache Spark |
|----------|--------------|----------------|---------|--------------|
| **Наличие конфигурации CRON-расписания** | ✅ Встроенная поддержка через `@Scheduled` и `TaskScheduler` | ✅ Нативный CRON через `schedule_interval` | ⚠️ Требует настройки CronJob в Kubernetes | ❌ Отсутствует, требует внешнего планировщика |
| **Сложность реализации логики по обработке данных** | ✅ Низкая. Java/Kotlin с Spring экосистемой | ⚠️ Средняя. Python, но избыточен для простых задач | ⚠️ Средняя. Требует контейнеризации | ❌ Высокая. Избыточен для малых данных |
| **Ресурсоёмкость решения** | ✅ Низкая. Легковесное Spring Boot приложение | ⚠️ Средняя. Требует БД, веб-сервер, планировщик | ✅ Низкая. Запуск только во время выполнения | ❌ Высокая. Требует кластер, много памяти |
| **Масштабируемость под нагрузкой** | ✅ Хорошая. Вертикальное и горизонтальное масштабирование | ✅ Отличная. Распределенные воркеры | ✅ Хорошая. Нативная оркестрация K8s | ✅ Отличная. Кластерные вычисления |
| **Сложность развёртывания в облаке и интеграция с микросервисной архитектурой** | ✅ Низкая. Стандартный Spring Boot микросервис | ⚠️ Средняя. Требует отдельного развертывания | ✅ Низкая. Нативное для облачной инфраструктуры | ❌ Высокая. Требует кластерной настройки |
| **Удобство интеграции с системами логирования и мониторинга** | ✅ Отличное. Spring Actuator, Sleuth, Micrometer | ⚠️ Среднее. Встроенные, но требуют настройки | ⚠️ Среднее. Требует интеграции с EFK/Prometheus | ❌ Сложное. Специфические системы мониторинга |

## Выбранное решение: Kubernetes CronJob + Spring Boot (Spring Batch)

## Обоснование выбора

### 1. Идеальное соответствие требованиям

- **Простая ETL-задача без сложной обработки** — не требуется сложная логика трансформации данных, только JOIN и выгрузка.
- **Фиксированное время запуска (6:00 утра)** — CronJob нативно поддерживает периодический запуск по расписанию.
- **Небольшой объем данных (5 000-10 000 строк)** — не требует распределенной обработки в Spark, достаточно однопоточного выполнения в Spring Batch.
- **Отсутствие необходимости в real-time обработке** — batch-ориентированный подход полностью покрывает потребности задачи.

### 2. Минимальные накладные расходы

- **Airflow избыточен для одной простой задачи** — поднятие полноценного Airflow-кластера (веб-сервер, планировщик, Celery/Redis, БД) ради одной ежедневной задачи нерационально.
- **Spark избыточен для малого объема данных** — кластерные вычисления не нужны для обработки 10 000 строк, overhead на управление кластером превышает полезную работу.
- **Spring Batch + K8s CronJob — легковесное решение** — Pod запускается только на время выполнения (несколько минут в день), потребляя минимум ресурсов.

### 3. Нативная облачная интеграция

- **Органично вписывается в существующую микросервисную архитектуру** — используется тот же технологический стек (Spring Boot, Docker, K8s), что и в других сервисах.
- **Использует существующие механизмы K8s**:
    - Логирование: автоматический сбор логов в ELK через Filebeat.
    - Мониторинг: метрики Prometheus через Actuator.
    - Секреты: K8s Secrets для хранения паролей и ключей доступа.
- **Не требует дополнительной инфраструктуры** — в отличие от Airflow, который требует отдельного кластера и обслуживания.

### 4. Простота поддержки

- **Единый технологический стек с другими микросервисами** — Java + Spring Boot знаком команде разработки, не требует изучения нового языка (Python) или парадигмы.
- **Стандартные практики CI/CD** — стандартный Dockerfile, Helm-чарт или kubectl apply.
- **Встроенная интеграция с системами мониторинга**:
    - Spring Actuator + Micrometer → Prometheus → Grafana.
    - Логи → Elasticsearch, Fluentd, Kibana (EFK).
    - Автоматические health-check'и и алерты.

### Вывод

**Kubernetes CronJob + Spring Boot (Spring Batch)** — оптимальное решение, обеспечивающее баланс между функциональностью, простотой, стоимостью владения и интеграцией в существующую облачную инфраструктуру.

# Задание 6: синхронный запуск ETL и трассировка

Решение содержит React-клиент, Spring Batch API и локальный сбор логов через Filebeat → Logstash → Elasticsearch → Kibana. Код приложения основан на задании 5, но использует отдельные контейнеры, порты и тома. Задание не стартует вместе с приложением: его запускает только `POST /jobs/import`.

## Запуск

Нужны Docker Compose, доступ к Docker Hub, Elastic и Maven, а также свободные локальные порты 8081, 8082, 5434, 9201, 5602. Команды из каталога `task-6/solution`:

```bash
docker compose up -d --build
docker compose ps
```

При первом запуске PostgreSQL создаёт таблицы и загружает справочник; ELK может запускаться несколько минут. Откройте <http://localhost:8082> и нажмите **«Запустить обработку»**. Клиент ожидает окончания обработки и показывает её статус, номер запуска и `traceId`.

Альтернативно — запрос к API:

```bash
curl -i -X POST http://localhost:8081/jobs/import
```

Ответ при успехе:

```json
{"executionId":1,"status":"COMPLETED","traceId":"...","message":null}
```

При ошибке задания API возвращает HTTP 500, статус `FAILED` или `ERROR` и, при доступном контексте, `traceId`. Подробности ошибки находятся в логах. Каждый запрос создаёт новый экземпляр задания; данные товара обновляются по `productId`. Обработка выполняется синхронно в потоке запроса, поэтому до её завершения браузер ожидает ответ. Тайм-аут прокси составляет 120 секунд; это демонстрация, а не решение для длительных задач.

Проверить товары:

```bash
docker compose exec postgresdb psql -U postgres -d productsdb -c 'SELECT * FROM products ORDER BY productId;'
```

## Поиск трассы в Kibana

1. Дождитесь появления индекса: `curl 'http://localhost:9201/_cat/indices/tradeware-task6-*?v'`.
2. Откройте <http://localhost:5602>, в **Stack Management → Index Patterns** создайте `tradeware-task6-*`, выберите поле времени `@timestamp`.
3. В **Discover** выберите шаблон и нужный диапазон времени. Вставьте `traceId` из интерфейса в фильтр KQL:

   ```text
   traceId: "вставьте_идентификатор"
   ```

4. Добавьте колонки `traceId`, `spanId`, `uri` и `message`. Должны быть видны события получения HTTP-запроса, выполнения задания и ответа с одинаковым `traceId`. `spanId` может отличаться: наблюдение Spring Batch создаёт вложенные операции.

Если логов пока нет, проверьте `docker compose logs filebeat logstash app`. Сервер поддерживает входящий W3C `traceparent`; если заголовка нет, контекст создаётся сервером. При ошибке до создания серверного контекста идентификатор может отсутствовать.

## Ограничения

Приложение читает CSV из образа, а не произвольный загруженный файл. Промышленная аутентификация, TLS, хранение секретов, политика хранения индексов и сбор самих span в Jaeger/Tempo здесь не реализованы: идентификаторы используются для связи логов. Данные записываются порциями и могут стать видимыми до завершения всего файла. Сервис и порты предназначены только для локального запуска.

`docker compose down` останавливает окружение, сохраняя тома. Команда с `-v` удаляет тома и все данные задания 6.

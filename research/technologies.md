# Технологии проектной работы спринта 5

Документ содержит общую карту технологий для всей проектной работы Task1–Task6. Это исследовательский материал, а не
часть решения отдельного задания.

## Карта по заданиям

| Задание | Основные технологии и подходы                                                                     |
|---------|---------------------------------------------------------------------------------------------------|
| Task1   | Apache Airflow, PostgreSQL, CSV, HTTP API, Kafka, BigQuery, Redshift, Spark, SMTP, Docker Compose |
| Task2   | Spring Batch, Apache Airflow, Kubernetes Job, Spark, C4, Draw.io                                  |
| Task3   | Kubernetes CronJob, Docker, PostgreSQL, CSV, Minikube                                             |
| Task4   | Java, Spring Batch, PostgreSQL, Docker Compose, ETL, ADR, C4                                      |
| Task5   | Prometheus, Micrometer, Grafana, Alertmanager, ELK, Filebeat, Docker Compose                     |
| Task6   | REST API, Micrometer Tracing, Brave, W3C Trace Context, ELK                                       |

## 1. Подходы пакетной обработки

Это архитектурные подходы и параметры, а не отдельные программные продукты.

| Подход и тип                                      | Назначение                                                     | Использование в проекте                             |
|---------------------------------------------------|----------------------------------------------------------------|-----------------------------------------------------|
| **Batch processing — способ обработки данных**    | Обработка ограниченного набора данных отдельными запусками     | Основа всех заданий спринта                         |
| **ETL — архитектурный шаблон**                    | Извлечение, преобразование и загрузка данных                   | Реализуется в Task4                                 |
| **MapReduce — модель распределённых вычислений**  | Параллельная обработка частей данных и объединение результатов | Рассматривается в теории спринта                    |
| **Distributed Scheduling — архитектурный подход** | Координация запуска jobs между несколькими узлами              | Применяется в Task3 и рассматривается через OpenJob |
| **Batch size — параметр обработки**               | Баланс скорости, памяти, нагрузки на БД и стабильности         | Учитывается при проектировании batch jobs           |

## 2. Оркестрация и выполнение jobs

| Технология и тип                                                            | Назначение                                                                 | Использование в проекте                                                       |
|-----------------------------------------------------------------------------|----------------------------------------------------------------------------|-------------------------------------------------------------------------------|
| **Apache Airflow — оркестратор data pipelines**                             | Управляет DAG, зависимостями, ветвлением, retry, событиями и уведомлениями | Основное решение Task1 и вариант для сравнения в Task2                        |
| **Spring Batch — Java-фреймворк пакетной обработки**                        | Реализует чтение, обработку и запись данных через Job и Step               | Основная технология Task4 и вариант для сравнения в Task2                     |
| **Spring Cloud Data Flow — платформа управления batch/stream applications** | Запускает и отслеживает Spring Batch-приложения                            | Дополнительный вариант для Spring Batch; явно не требуется программой проекта |
| **Kubernetes Job — ресурс одноразового запуска**                            | Запускает контейнер до успешного завершения задачи                         | Основа запуска приложения в Task3                                             |
| **Kubernetes CronJob — ресурс периодического запуска**                      | Создаёт Kubernetes Job по CRON-расписанию                                  | Основная технология Task3                                                     |
| **OpenJob — фреймворк распределённого планирования**                        | Поддерживает cron jobs, workflow, MapReduce и распределённое выполнение    | Рассматривается в теории Distributed Scheduling                               |
| **Apache Spark — распределённый движок обработки данных**                   | Выполняет параллельную batch- и stream-обработку                           | Интеграция Task1 и вариант для сравнения в Task2                              |

Оркестратор управляет процессом, а движок обработки выполняет вычисления. Например, Airflow может запустить Spark job и
дождаться результата.

## 3. Источники, хранилища и интеграции

| Технология и тип                                                    | Назначение                                                     | Использование в проекте                            |
|---------------------------------------------------------------------|----------------------------------------------------------------|----------------------------------------------------|
| **PostgreSQL — реляционная строковая СУБД**                         | Хранение транзакционных и справочных данных                    | Источник в Task1–Task3 и основная БД Task4         |
| **Google BigQuery — serverless колоночное аналитическое хранилище** | Выполнение аналитических запросов над большими наборами данных | Требуемая интеграция Task1                         |
| **Amazon Redshift — облачное колоночное MPP-хранилище**             | Аналитическое хранение данных в AWS                            | Требуемая интеграция Task1                         |
| **Apache Kafka — event-streaming платформа и брокер сообщений**     | Передача и хранение событий                                    | Источник событий и event trigger в Task1           |
| **Google Cloud Storage — объектное хранилище**                      | Хранение файлов отчётов                                        | Часть исходной архитектуры TradeWare в Task4–Task6 |
| **CSV/XLS — табличные форматы данных**                              | Обмен пакетными данными через файлы                            | Источники и результаты в Task1–Task4               |
| **HTTP/REST API — программный интерфейс взаимодействия**            | Вызов внешних сервисов и запуск операций                       | Интеграция Task1 и способ запуска ETL в Task6      |
| **SMTP — почтовый протокол**                                        | Отправка email-уведомлений                                     | Успешные и неуспешные запуски Task1                |

## 5. Мониторинг, логирование и трейсинг

| Технология и тип                                            | Назначение                                                    | Использование в проекте               |
|-------------------------------------------------------------|---------------------------------------------------------------|---------------------------------------|
| **Prometheus — система мониторинга и time-series database** | Сбор и хранение метрик                                        | Основная система метрик Task5         |
| **Micrometer — Java metrics facade**                       | Публикация прикладных и JVM-метрик                            | Метрики Spring Batch через Actuator в Task5 |
| **JMX Exporter — Prometheus exporter и Java agent**         | Альтернативная публикация JMX-метрик в формате Prometheus     | Возможная альтернатива для Task5      |
| **Grafana — платформа визуализации и оповещений**           | Дашборды, запросы к источникам метрик и alerts                | Визуализация и оповещения Task5       |
| **Alertmanager — менеджер оповещений Prometheus**           | Группировка, маршрутизация и доставка alerts                  | Возможный механизм оповещений Task5   |
| **ELK — стек централизованного логирования**                | Сбор, хранение, поиск и отображение логов                     | Task5 и Task6                         |
| **Elasticsearch — поисковая и аналитическая NoSQL-система** | Индексация и поиск логов                                      | Хранилище логов ELK                   |
| **Logstash — инструмент обработки и доставки данных**       | Преобразование и передача логов                               | Компонент ELK                         |
| **Kibana — интерфейс анализа данных Elasticsearch**         | Поиск и визуализация логов                                    | Демонстрация логов Task5 и Task6      |
| **Filebeat — lightweight log shipper**                      | Чтение файлов логов и отправка в Elasticsearch или Logstash   | Сбор логов Spring Batch в Task5–Task6 |
| **Micrometer Tracing — Java tracing facade**                | Интеграция trace-контекста с наблюдаемостью Spring Boot        | Основа трейсинга Task6                |
| **Brave — реализация distributed tracing**                  | Создание span и поддержка W3C Trace Context                    | Tracing bridge в Task6                |
| **W3C Trace Context — стандарт передачи trace-контекста**   | Передача `traceId` и родительского `spanId` в `traceparent`    | Связь Java-клиента и API в Task6      |
| **OpenTelemetry — стандарт и инструментарий observability** | Создание и передача метрик, логов и трассировок                | Возможный production-вариант Task6    |
| **Trace ID — идентификатор распределённого запроса**        | Связывает операции одного запроса                             | Обязательное поле логов Task6         |
| **Span ID — идентификатор операции внутри trace**           | Выделяет отдельный участок обработки запроса                  | Обязательное поле логов Task6         |

ELK и OpenTelemetry также входят в теорию спринта 5. Конкретная конфигурация выбирается при выполнении Task5 и
Task6.

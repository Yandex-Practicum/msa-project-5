# Решение для пакетной обработки данных (Task 1)

## 1. Обоснование выбора технологического решения

Для реализации задачи пакетной обработки данных маркетингового отдела выбран оркестратор **Apache Airflow**.

### Почему Airflow?
1.  **Гибкость пайплайнов:** Airflow использует концепцию DAG (Directed Acyclic Graph), что позволяет визуально проектировать, ветвить и управлять зависимостями задач. Код пайплайна пишется на Python, что дает полную программную гибкость.
2.  **Экосистема интеграций:** Airflow имеет богатую библиотеку Providers.
    *   **BigQuery/Redshift:** Существуют готовые операторы (`BigQueryInsertJobOperator`, `RedshiftSQLOperator`), позволяющие выполнять SQL-запросы и загрузку данных без написания драйверов.
    *   **Kafka:** Интеграция через `KafkaProducerOperator` или хуки для чтения/записи сообщений.
    *   **Spark:** Оператор `SparkSubmitOperator` позволяет запускать Spark-джобы на кластере (YARN, K8s, Standalone) прямо из пайплайна.
    *   **PostgreSQL/CSV:** Встроенные хуки для работы с БД и файловой системой.
3.  **Логика выполнения:**
    *   **Ветвление:** Реализуется через `BranchPythonOperator`.
    *   **Условные операторы:** Стандартный Python внутри `PythonOperator`.
    *   **Event-triggers:** Сенсоры (`Sensors`) для ожидания событий (файл, запись в БД, сообщение в Kafka).
4.  **Надежность и мониторинг:**
    *   **Retry:** Встроенная политика повторных попыток (`retries`, `retry_delay`).
    *   **Fallback/Alerts:** Поддержка callback-функций (`on_failure_callback`, `on_success_callback`) для отправки уведомлений.
    *   **Email:** Встроенный `EmailOperator` и настройка SMTP в конфигурации.
5.  **Развертывание в облаке:**
    *   Airflow легко контейнеризируется (Docker).
    *   В облаке может быть развернут как управляемый сервис (Google Cloud Composer, AWS MWAA) или на собственном Kubernetes-кластере (Helm-чарт Astronomer/Official), что обеспечивает масштабируемость под нагрузку в 1 млн+ записей (оркестрация + запуск тяжелых вычислений на Spark/Cloud DW).

## 2. Описание POC (Proof of Concept)

Демонстрационный пайплайн `marketing_pipeline` реализует следующие требования:
1.  **Чтение данных:** Имитация чтения из CSV (источник статусов доставок).
2.  **Ветвление:** Анализ данных. Если найдены статусы "ERROR", пайплайн идет по ветке алерта, иначе — по ветке успеха.
3.  **Retry-политика:** Задача `process_data` настроена на 2 повторные попытки. В демонстрации она намеренно падает первый раз, чтобы показать механизм retry.
4.  **Уведомления:** Настроены callback-функции для отправки email (симуляция в логах) при успехе и неудаче всего DAG.

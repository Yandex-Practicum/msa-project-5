# Задание 4. Пакетная обработка товаров

В каталоге находится локальный пример Spring Batch. Исходный шаблон находится в `../initial`, справочная реализация — в `../complete`, архитектурные материалы и результаты проверки — в `../results`.

## Запуск

Нужны Docker и Docker Compose, доступ к реестрам Docker и Maven. Из каталога `task-4/solution`:

```bash
docker compose up --build --abort-on-container-exit --exit-code-from app
```

При первом запуске PostgreSQL создаёт таблицы и загружает `src/main/resources/loyality_data.csv`. Приложение читает `src/main/resources/product-data.csv` без заголовка и завершает работу после задания. В логе ожидается статус `COMPLETED`. Учётные данные в compose предназначены исключительно для локального примера. Порт 5432 должен быть свободен.

Эта команда предназначена для первого запуска на пустой БД. Для повторной обработки уже успешно загруженного файла используйте команду с новым `run.id` ниже.

Проверка данных после завершения (команда снова запустит только БД):

```bash
docker compose up -d postgresdb
docker compose exec postgresdb psql -U postgres -d productsdb -c 'SELECT * FROM products ORDER BY productId;'
docker compose exec postgresdb psql -U postgres -d productsdb -c 'SELECT job_name, status, exit_code FROM batch_job_execution JOIN batch_job_instance USING (job_instance_id);'
```

Ожидаются пять товаров; у SKU 20001, 30001 и 50001 поле `productData` меняется на `Loyality_on`; у 40001 остаётся значение из CSV, так как записи в справочнике нет. Значение 60001 также равно `Loyality_on`.

Повторный запуск как нового задания:

```bash
docker compose run --rm app --spring.batch.job.name=importProductJob run.id=2
```

Для следующего нового запуска используйте другое значение `run.id`. Без изменения параметров Spring Batch не запустит уже успешно завершённый экземпляр. При ошибке повтор с теми же параметрами возобновляет незавершённое задание при неизменном входном файле. Обновление товаров по `productId` не создаёт дубликаты. Изменения фиксируются порциями по 100 строк, поэтому до завершения задания часть результатов может быть видна.

```bash
docker compose stop
```

Данные сохраняются в томе `pgdata`. Скрипты инициализации запускаются только при создании пустой БД; изменение CSV справочника само по себе не обновит существующий том. Для новых входных данных приложения измените CSV и пересоберите образ. Это демонстрационный запуск, не интерфейс загрузки файлов.

## Устройство

`FlatFileItemReader` читает CSV, процессор проверяет основные поля, `JdbcBatchItemWriter` записывает порцию через JDBC. При записи PostgreSQL выбирает данные лояльности по индексированному SKU и обновляет `products` по `productId`. При отсутствии SKU в справочнике сохраняется исходное значение. Ошибочная строка останавливает задание, текущая порция откатывается; пропуск строк и повтор временных ошибок в POC не настроены. Справочник может измениться во время обработки — согласованный снимок для всего файла здесь не гарантируется.

`../results/ADR.md` и `../results/C4.md` описывают предлагаемую целевую систему, а не только реализованный POC. Нагрузочные показатели и облачная интеграция этим примером не подтверждены.

Скриншоты выполнения задания и результата запроса к таблице `products` приведены в [результатах задания](../results/README.md#результат-работы-приложения).

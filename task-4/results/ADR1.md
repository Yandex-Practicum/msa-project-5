### <a name="_3bfxc9a45514"></a>**Функциональные требования**

|**№**|**Действующие лица или системы**|**Use Case**|**Описание**|
| :-: | :- | :- | :- |
| UC1 | Работник на складе | Загрузка отчета по остаткам | Сотрудник выбирает csv отчет. Загружает файл через веб-интерфейс. Система валидирует формат и целостность данных. Файл сохраняется в GCS. Запускается ETL-процесс: чтение данных из CSV, обогащение справочными данными из Postgres, обновление таблицы. Пользователь получает уведомление об успешной обработке или ошибк |

### <a name="_u8xz25hbrgql"></a>**Нефункциональные требования**

|**№**|**Требование**|
| :-: | :- |
| 1 | Хорошая масштабируемость. Горизонтальное масштабирование + интеграция с микросервисами |
| 2 | Хорошая надежность. Ретраи, транзакционная обработка, observability |
| 3 | Производительность. Обработка отчета на около 2тыс строк в среднем за 30сек + поддержка 150-200 параллельных пиковых загрузок |
| 4 | Совместимость с текущим стеком |

### <a name="_qmphm5d6rvi3"></a>**Решение**

* Интеграция Spring Batch в существующий монолит как отдельный компонент для пакетной обработки ETL. Это позволит разгрузить компоненты, перенеся тяжелый операции по типу обогащегия в фоновый режим. Spring Batch будет запущен как часть Java-приложения с использованием docker для локальной разработки и GCP для прода.
* Spring Batch выбран т.к. у команды есть опыт + совместимость с java экосистемой и встроенных фич для ETL по типу ретраи, chunk-processing и т.п.
* Batch поддерживает валидацию/обогащение в processor + batch-записи для производительности

### <a name="_bjrr7veeh80c"></a>**Альтернативы**
* Apache Spark. Для больших данных хорошо масштабируется, поддерживает ETL с DataFrames. Подходит для пиковых нагрузок >1M строк. Может быть альтернативой для будущего роста.
* Apache Airflow. Хорошая оркестрация, но это дополнительный стек в виде Python, поэтому потребуется интеграция с jvm.

**Недостатки, ограничения, риски**

* Зависимость от spring-экосистемы. Будет сложно в дальнейшем интегрировать с не java компонентами, если потребуется.
* Максимальный размер чанка ограничен памятью jvm. При масштабировании может быть проблема.

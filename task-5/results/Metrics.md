# Обоснование выбранных метрик для мониторинга

* Метрики собираются через Prometheus c использованием встроенного эндпоинта `/actuator/prometheus` и кастомных метрик через Micrometer.


### Метрики
1. batch.job.duration - время выполнения spring batch job, измеряемое с помощью micrometer timer. Позволяет отслежить производительность ETL. Tags: job_name, status
2. loyalty.updates.total - счетчик успешных обновлений даннных в ProductItemProcessr, измеряется Micrometer counter. Отслеживает объем обработнных данных, оценивает эффективность ETL.
3. loyalty.updates.failed - количество неуспешных обновлений. Помогает выявлять ошибки в данных или логике обработки.
4. jvm_memory_used_bytes - отражает объем использованной памяти JVM. Используется в качестве метрики для мониторинга здоровья приложения.

### Обоснование выбора

* Измерение производительности ETL. Метрики позволяют обеспечить контроль времени выполнения задач и API
* Измерение качества данных. Метрики позволяют отслеживать успешность обработки данных, чтоо важно для бизнес-логики
* Измерение здоровья приложения. Метрики позволяют отслеживать состояние JVM и мониторить его здоровье
